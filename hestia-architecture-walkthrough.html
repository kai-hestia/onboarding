0速览 TL;DR

30 秒建立心智模型，后面每节再展开。

  • 整个系统是 云 → 门店 Roboserver → 机器 三层。真正在做菜的是机器，指挥做菜的是门店的 hcms，接单的是 eats-gw，配方从云端一路同步下来。
  • larder-api 是 Larder 柜机这一台的本地后端：对 UI 提供 REST + SSE，对上游（hcms / hcsui-gw）提供 gRPC，对下通过 MQTT 指挥控制器（硬件略）。
  • larder-ui 是一套 Vue 3 + Vite 的触屏前端，构建产物被 larder-api 以 /ui 路径托管，前后端同机部署。
  • Dispenser 和 MC1~3 是同构的另外两套机器（sauce-dispenser-api/ui、mc-api/mc-ui）。吃透 Larder 一套，另外两套触类旁通。
看图口诀 橙色虚线框 = 机器内部三件套（ui / api / controller）；中间的 Roboserver 框 = 门店大脑与集成层；最上方 = 云端；右下 = 可观测性（Datadog）。

2.2 启动流程

// cmd/ldapi/ldapi.go（伪代码梳理）
读 config.yaml（viper）
 → log 初始化 + SocketHook（日志转发）+ goroutineID hook
 → patches.hotFix()               // 按日期打的老机器兼容补丁
 → stacks.InitInventory()         // 读 configs/stacksInfo.json（84 格库存）
 → models.InitControllerComm()    // 建立 MQTT 连接

 → stacks.InitPositionMap()       // 读 configs/positionsInfo.json（XY 坐标）
 → go initRouter()                // Gin :3000，托管 ~/larder-api/ui
 → initGrpcServer()               // :40050 srcomm 服务

前端同学重点是下面这些。SSE（Server-Sent Events）是这套 UI 实时性的全部来源。

分组接口用途

实时（SSE）/inventory/quantitySse库存变化推送

2.5 对上游：gRPC srcomm

  • 调用方是 hcms（调度脑）与 hcsui-gw（HMI 网关），它们都作为 srcomm client 连这台机器的 :40050。
  • PickPlace 是阻塞式的：校验状态 → 发 MQTT 给控制器 → 每 50ms 轮询 FSM 状态直到成功 / 失败 / 超时；另有流式版本 PickPlaceStream。
  • GetSystemInfo 返回的 state 决定这台机器对 hcms 是 IDLE / PROCESSING / NOT_OPERATING / UNAVAILABLE，metadata 里带库存、温度、进度。hcms 每 500ms 轮询一次（hcms/internal/hmc/srm.go）。
// srcomm 服务（hcms-core/api/srcomm/srcomm.proto）
GetSystemInfo · PickPlace · Deliver · StacksQuery · StacksUpdate
GetState · OnlineRequest · Cancel

2.6 配方 / 库存同步

  • 暴露 POST /upload：body 是整份 stacksInfo.json 映射，由 recipe-updater 推送（rfm6.go 里请求 http://<larder-ip>:3000/upload）。
  • setMultipleQuantity 支持 UI 或运维手动改库存。
  • 自升级：/setting/checkUpdate、/setting/update 从 GitHub Releases 拉取 larder-api / larder-ui / larder-control / stm32 制品（见 config update.*）。
配置注意 仓库里的 configs/config.yaml 是开发机配置（Windows 绝对路径 D:/hestia/...）。本地跑之前先改成你的路径；生产路径是 /home/orangepi/ld-api/。

4周边服务串讲

每台机器之外的部分：门店集成层与云端。

4.1 门店 Roboserver（edge PC）

部署见 kitchenos-deployment/compose/（docker compose + mosquitto + mongo + datadog-agent）。

服务技术 / 端口一句话职责关键连接
hcms Go · gRPC :40031 本地"调度大脑"：订单拆 Task，编排 srm / sf / dpc / bus 各机器；配方合并、deliver_delay、告警 对上被 hcsui-gw、eats-gw 调用；对下作为 client 调 larder-api :40050，或经 MQTT 控 dispenser / MC / 传送带
hcsui-gw Go · GraphQL :8180 门店 HMI 网关 / BFF：鉴权（JWT + API key），聚合 hcms + mongo，向 recipes-api-v2 同步配方 → hcms:40031；→ mongodb；→ recipes-api-v2
hcsui Vue 2 + Vuetify + Vue Apollo 店员/运维看板：订单进度、RF 设置、系统设置（HMIV1.vue 等） → hcsui-gw GraphQL
eats-gw Go · HTTP :8180（路由器把外网 80 转发过来） 订单入口：收 POS / 外卖平台下单，解密 → 配方修正/合并 → 调 hcms AddJob 接口：/v1/send-job、/v1/api-enabled、/v1/check-status、/v1/job-history
square-gw Go + SQLite 轮询 Square 支付单，catalog → Hestia 产品码映射，加密后 POST 到 eats-gw → Square API；→ eats-gw /v1/send-job
recipe-updater Go · :20000 配方/库存下发器：WebSocket /update?machineId=，从 recipes-api-v2 拉配方与 box 映射，写到各机器 larder：:3000/upload；炒锅类：/menu/upload；→ recipes-api-v2
iotcbridge Node.js（azure-iot-device） Azure IoT Central 设备接入（DPS 注册、设备孪生、C2D）：云端 slot 变更写 mongo，再触发 recipe-updater → Azure IoT；→ mongo；→ updater
mongodb / mosquitto 容器 本地配方/产品/合并库；MQTT broker（hcms ↔ dispenser / MC / bus 的命令总线） hcms_network
datadog-agent 容器/宿主 日志与指标采集：larder-api socket hook 打 23336、dispenser 23337，hcms 读文件 → Datadog

入口图上的 hmiproxy 类入口在 deployment 里也有：nginx 反代 + frp / cloudflared 隧道，用于远程访问门店与柜机。

6本地联调起手式

复制即可跑，先把 Larder 一条线打通。

# ---------- 后端 ----------
cd ~/repos/larder-api
go mod tidy        # 需要 GOPRIVATE=github.com/Hestia-Technology/*
go build -v ./cmd/ldapi
./ldapi -c configs/config.yaml    # 先把 config 里 Windows 路径改为本机；HTTP :3000 / gRPC :40050

# ---------- 前端 ----------
cd ~/repos/larder-ui
npm install
npm run dev        # :5173，直连本机 :3000

# ---------- MQTT 自测（README 有）----------
mosquitto_sub -p 1883 -t "/larder/ctrl/cmd/" -v
mosquitto_pub -p 1883 -t "/larder/ctrl/cmd/" -m "FSM_SETTINGS 4"

# ---------- 机器上查日志 ----------
tail -n 200 -f /home/orangepi/ld-api/log/ldapi-<date>.log
tail -n 500 ld-api.log | jq -r 'del(.file, .func) | ...'   # README 里有完整 jq 过滤命令

发布纪律

main 禁止直接 push，走 PR + CI（build / lint / unit test）。

发版前手动改版本号：internal/settings/machine_setting.go 的 BackendVersion（当前 v6.0.18）。

发布机制

打 tag → GitHub Actions（GoReleaser / Vue Release）产出制品 → 机器上 /setting/update 自动拉取。

7风险与注意事项

① 明文 GitHub PAT 已提交进 git 历史 ⚠ configs/config.yaml 里的 github_token: ghp_... 不是本地改动，git show HEAD:configs/config.yaml 可以直接看到。建议尽快轮换该 token，并改造成环境变量 / Secret 注入（GitHub Actions 里已经在用 secrets 了）。
② CORS 配置过宽 AllowOrigins: ["*"] + AllowCredentials: true：浏览器规范下这种组合不可靠，且有安全风险。生产应改为白名单（localhost:5173、柜机自身 IP 等）。
③ 配置文件的本地路径 configs/config.yaml 目前是开发机配置（D:/hestia/...），克隆后必须改，否则起不来。
④ 缓存策略有意为之 index.html no-store、/ui/assets/* immutable，是为了避免 Vite 构建后客户端拿到旧入口、动态 import 失败——不要"顺手优化"掉。
