0速览：两个仓库是什么

MC（Multicooker，多锅炒菜机）这一台机器上的"前端 + 后端"两件套。

mc-ui multicooker-ui

跑在机器触摸屏上的 Vue 3 应用（800×1280 竖屏）。点菜、做菜流程、主厨模式、清洁、设置、App Library 都在这里。

npm run dev → :3001；npm run build → ui/ → ui.zip → 上传 Azure Blob。

mc-api multicooker-api / multicooker-data

机器上的 Node.js (Express) 本地服务，:3000。持有机器状态、串口协议、MQTT、菜单文件、设置、升级逻辑，并托管 mc-ui 的构建产物。

systemd 服务 multicooker.service，WorkingDirectory /multicooker，node ./index.js。

一句话关系 mc-api 是"机器的操作系统接口"，mc-ui 是"机器的脸"。浏览器加载的是 mc-api 静态托管的 mc-ui 页面，页面再通过 HTTP + WebSocket 跟 mc-api 交互。

1mc-ui ↔ mc-api 架构

数据怎么流动，谁调用谁。

浏览器 / 触摸屏 Chromium800×1280
▼ 加载 http://<机器IP>:3000/（mc-api 托管 ui/ 静态产物）
mc-uiVue 3 SPA
⇄
mc-api :3000Express + express-ws
▼ HTTP：/menu /settings /machine /update ／ WS：/machine/status
串口协议serialcom · CRC16 · 100Hz buffer
MQTT/cm/<id>/cmd · /cm/<id>/error
Azure Blobui.zip / api.zip / firmware
▼ 硬件/控制板细节略
控制板（PIC32）电机 / 加热 / IO

注意方向：mc-ui 不直接连串口/硬件，所有动作都是 send_cmd(...) → HTTP /machine/cmd?cmd=... → mc-api 编码后走串口。MQTT 是"云端/门店 hcms → 机器"的反向指令通道（比如 COOK <recipeId>）。

2.1 全局能力（src/main.js）

main.js 把一堆函数挂在 app.config.globalProperties 上，所有 .vue 里直接 this.xxx() 用：

全局函数 / 对象作用
api_server_get(path, cb, err_cb)axios 封装，请求 http://${api_server_ip}:${api_server_port}${path}（30s 超时）
send_cmd(cmd)核心动作接口：GET /machine/cmd?cmd=...，如 COOK 12、online 0、pausecook 1
get_menu() / get_recipe(id)拉菜单目录与单个菜谱内容，缓存进 GlobalProps
show_popup(name, params)打开预定义弹窗（defs/popup_defs.js），如 sleep_confirm、restart_confirm
restart()调 /machine/restart 并跳转 /start（App Library 底部按钮走 popup → 这里）
GlobalProps / MachineStatusPinia store，分别对应"UI 状态"和"机器实时状态"
settings来自 src/settings.mjs：version、api_server_ip/port、宽高、num_ingredients、两个开关
version_get() / serial_number_get()拼 firmware+ui+api 版本、读 SN（用于 Machine ID 页）
 
// src/settings.mjs —— 前端唯一静态配置
version: '6.0.8.0',
api_server_ip: '10.93.2.142',   // 默认被当前 URL 的 host 覆盖（见下方说明）
api_server_port: 3000,
width: 800, height: 1280,       // 设计画布，App.vue 用它居中
num_ingredients: 7,
custom_server_origin: false,    // true = 用上面的固定 IP，不跟随 URL
disable_route_status: false     // true = 关闭"状态驱动跳转"，调试必备
IP 从哪来 main.js 里 const origin_ip = document.URL.split(/\/|:/)[3]：只要 custom_server_origin=false，前端就用"当前页面的 host"作为 API 地址 —— 所以机器上直接用机器 IP 打开即可；开发时把 custom_server_origin 改成 true 并填 API 的 IP。

2.2 状态驱动的路由（重点，改页面前必读）

mc-ui 的页面不是用户想去哪就去哪——机器状态会强制导航：

  1. main.js 建立 WebSocket ws://<ip>:3000/machine/status，把收到的 JSON 整个覆盖进 MachineStatus store（含 MachineStatusPrev）。
  2. 每次收到消息调用 protocol.js 的 route_machine_status(global)，规则包括：
    • server_state === 'SLEEP' → 强制 /sleep
    • server_state === 'FAILURE' → 强制 /error
    • system_state === 'ERROR' → 按错误码跳 /error?error_name=gripper|overheat|emo
    • 开始做菜 → 自动进烹饪页；做完 → 弹 order_completed 等
    • alert_id → 各种弹窗（alert_id_to_popup_name）
  3. 例外名单 route_exclude：/backend、/settings/general、/settings/factorysettings 不会被强制跳走。
调试开关 改新页面/新 App Library 条目时，如果被状态跳来跳去，先把 settings.disable_route_status = true（浏览器里按 Enter 键也会切回旧 IP + 打开这个开关，见 App.vue 的 keypress 监听）。

UI.js服务自愈：触摸屏存活检查（30s）、无 Chromium 客户端时重启服务（15s） GET /ui/log?log=（前端路由日志打点）

3.2 Machine：串口与状态广播

  • MachineStatus 是一个巨大的构造函数对象：version、server_state、system_state、online、alert_id、wok 温度、heating、cook（id/order_number/阶段/剩余时间/box_status）、io、motor、motion_state、settings… UI 那一堆 MachineStatus?.xxx 都来自它。
  • 串口命令 serial_cmd(line)：拆词 → COOK 特殊处理（初始化烹饪状态、解析订单号）→ 普通命令加帧长填充 + PC 版 CRC16 → 压入 100Hz 的 serial_buffer 由 10ms 定时器发送。文件下发则分块走同一 buffer。
  • 状态广播：ws_send_machine_status() 把整个 MachineStatus 逐客户端 send；每 1s 检查控制板存活，10s 无响应 → FAILURE / Controller Status Timeout。
  • 客户端数 /machine/clients + UI.start_chromium_check()：一个浏览器都不连就重启服务（防止白屏）。

4⭐ App Library 专章

你的下一个任务。它到底是什么、在哪、怎么改。

一句话定义 App Library 是 mc-ui 里的一个全屏半透明导航 Overlay（组件 AppsOverlay.vue），是机器的"功能抽屉"：主厨模式、换锅、清洁、补液、语言、设置、机器 ID、睡眠、重启。它是纯前端导航，不拉任何后端数据；个别条目会触发 mc-api 调用（sleep / restart）。

4.1 位置与触发方式

项内容

状态GlobalProps.show_apps（Pinia，src/stores/GlobalProps.js，默认 false）
挂载点src/App.vue：<AppsOverlay v-if="GlobalProps.show_apps"/>（和 PopUp / Restart / Language / QRCode 几个 Overlay 并列，z-index 1000）
标题 i18nhome.apps = 'App Library'（四种语言均有）
打开入口 ① Home.vue 顶栏右上角图标（assets/home/app_btn.svg）→ toggle_apps_on_off()（顺带 navigate_guard()：退出自动接单 + 弹 auto_accept_off）
② Menu.vue / Recipes.vue 顶栏右上角 → GlobalProps.show_apps=true
③ ChefsMode.vue 顶栏右上角 → show_apps=true
关闭TopBar 返回按钮（back_btn_callback="hide"）、点任意条目 navigate()、popup 回调/睡眠/重启时置 false

4.4 修改指南 + 避坑

典型改动清单（按照做即可）：

  • 新条目：图标 SVG 放 src/assets/home/ → 在 AppsOverlay.vue 复制一个条目 div → 加 $t key（i18n.js 的 en/ja/zh_Hans/zh_Hant 四个块都要加）
  • 如果是新页面：src/plugins/router.js 注册路由 → 页面放 views/ → 条目用 navigate('/xxx')；记得遵守 protocol.js 的状态跳转规则
  • 如果是确认类动作：在 src/defs/popup_defs.js 定义 popup（参考 sleep_confirm/restart_confirm），条目只写 show_popup('xxx_confirm')；popup 回调里记得 GlobalProps.show_apps = false
  • 调整顺序/分组：直接挪 template 里的 div，保持 horizontal_line 与 apps_item_gap 的节奏
  • 改间距/缩进：AppsOverlay.vue scoped 样式 + 全局 .horizontal_line 一起改（后者是全局类，影响面广）
  • 本地预览：npm run dev（3001），Home 页点右上角 app 图标即可看到 Overlay
  • 发布前：settings.mjs 与 version.js 版本号都要升 → 构建 → 上传（两个上传脚本都有守卫检查）
最容易踩的三个坑 ① 状态跳转：正在做菜/报警时 UI 会被 route_machine_status 强制跳走，测试新页面时先设 disable_route_status=true；
② /chefsmode 隐藏逻辑：in_chefsmode 只隐藏第一个条目，新增条目若也想隐藏要自己补判断；
③ Overlay 状态被打断：show_apps 会在 sleep/restart/popup 相关回调里被置 false，新增交互时留意别让遮罩"莫名关掉"。

5本地开发与发布

两台服务 + 一个浏览器，就能联调大部分 UI（除硬件动作）。

# ---------- mc-api（后端，需 Node） ----------
cd ~/repos/mc-api
npm install
npm start                    # :3000；首次运行自动生成 settings.json
                             # 默认 machine_name=CM1、remote_broker_ip=10.93.2.233、串口 /dev/ttyS9

# ---------- mc-ui（前端） ----------
cd ~/repos/mc-ui
npm install
npm run dev                  # :3001，vite
# 联调：把 src/settings.mjs 改为
#   custom_server_origin: true
#   api_server_ip: '<mc-api 所在机器 IP>'
# 或直接访问 http://<mc-api 机器>:3000/（走 mc-api 托管的构建产物）

# ---------- 构建 / 发布 ----------
# mc-ui:  version 改 src/settings.mjs
npm run build && npm run upload          # 测试：v6/test/ui.zip
npm run build && npm run upload-release  # 发布：v6/ui.zip
# mc-api: version 改 version.js
npm run build && npm run upload

# 需要 .env：AZURE_STORAGE_CONNECTION_STRING=...
# 机器端升级：访问 /update/updater 或用 /update/update?type=all[&test=1]

无硬件时怎么开发

mc-api 没串口也能起，状态会停在 FAILURE/超时；调 UI 页面足够。菜单数据可手动往 menu/ 里放 json（或调 /menu/upload）。

浏览器按 Enter 可以切换回固定 IP 并打开 disable_route_status（App.vue 里的调试快捷键）。

机器上的运行形态

systemd multicooker.service：WorkingDirectory=/multicooker，ExecStart=node ./index.js，启动后跑 ui_start.sh（拉起 Chromium 全屏）。

UI.js 每 15s 检查是否还有浏览器连着，没有就自动重启服务。
